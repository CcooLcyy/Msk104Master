# 工程骨架与验收边界

本文保留初始骨架交付边界。后续独立协议核心的实现与验收以 [协议内核首版](协议内核首版.md) 为准，桌面仍未接入协议会话。

## 本次交付

工程采用 Tauri 2 + Rust，首版范围包括中文桌面工作台骨架和连接参数的无副作用校验。现行构建流程通过 GitHub Actions 检查代码并生成 Windows 可执行文件。

## 结构与接口

- `crates/iec104-core`：不依赖桌面框架的配置与后续协议核心。
- `src-tauri`：桌面进程、日志、受控命令桥接。
- `src`：React/TypeScript 界面。
- `get_app_info`：返回应用名称、版本及 `protocol_ready=false`，不建立网络连接。
- `validate_connection`：输入 `config` 对象，字段为 `host`、`port`、`commonAddress`；成功返回空值，失败返回中文错误。仅接受 IP 或 ASCII 主机名、1～65535 端口及 1～65534 普通站公共地址，不执行 DNS 查询或网络通信。

## 骨架验收标准

1. 默认分支为 `main`，本地 `origin` 指向 GitHub 项目。
2. CI 对对应提交执行前端类型检查和生产构建、Rust 格式检查、Clippy 与单元测试，并编译 Windows 可执行文件。
3. 桌面程序显示未连接及协议功能尚未实现；无随机点值、伪造报文、隐式连接或命令发送。
4. 参数校验覆盖合法主机、非法主机、端口与公共地址边界；校验通过不能解释为连接成功。
5. 依赖锁文件纳入版本管理。依赖变更时一并更新并提交对应锁文件，由 CI 按锁定版本验证。

## 后续独立确定的功能

104 链路状态机、总召、遥测遥信、品质与时标、遥控遥调、事件流水、报文解析、证据导出及自动化服务尚未实现。后续先确定协议库、许可、输入输出和错误场景，再按测试优先方式推进。

总召、周期与自发上报应保留传送原因；点表最新值与接收事件流水分开保存。后续命令记录独立事务及确认阶段，接收事件记录单调序号和本机接收时间，以区分旧值与本轮操作后的更新。协议确认、DSP 内部状态与现场业务效果分别验证。
