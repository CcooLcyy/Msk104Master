# IEC104 协议内核首版

用户已确认先实现独立的关键协议内核。本轮范围为 Rust 核心与 CI 验证，桌面桥接、界面接线和真实设备联调分别后续验收。

## 实现选择与边界

使用 Rust 标准库实现有限范围的同步 TCP 主站与纯报文编解码，不增加运行时依赖，不依赖 Tauri 或 DSP 模块。现有成熟栈 lib60870 提供完整主从站能力，但本轮不引入 C FFI 或复制上游代码；首版不宣称完整标准一致性。协议语义核对参考上游 [用户指南](https://github.com/mz-automation/lib60870/blob/master/user_guide.adoc) 与 [主站 API](https://support.mz-automation.de/doc/lib60870/latest/group__CS104__MASTER.html)。

固定使用两字节传送原因、两字节公共地址、三字节信息地址。连接公共地址沿用 1～65534。首版无 TLS、安全认证、自动重连、遥控遥调、对时、文件服务或多站调度。DNS 解析通过系统解析器同步进行，不承诺 DNS 的超时上界。

## 输入输出与协议行为

- `wire` 层：增量分帧、I/S/U 帧编解码、总召 ASDU 构造、常用 ASDU 解析。无网络副作用。
- `session` 层：显式 TCP 连接、STARTDT/STOPDT、TESTFR、I 帧序号与确认、k/w 窗口及 t1/t2/t3 定时器。
- 调用者持续驱动 `poll`；不创建后台线程，不隐式重连。只有收到 STARTDT 确认后才允许总召。连接成功、数据传输开启、总召响应与现场业务效果是不同状态。
- 事件保留方向、完整原始帧与解析结果；未知 ASDU 保留原始帧并给出解析错误，不生成伪造点值。接收点对象保留 CA、IOA、COT、品质字节与原始 CP56Time2a；归一化值保留原始 i16，不擅自换算工程量。
- 支持类型 1/3/9/11/13 与 CP56Time2a 类型 30/31/34/35/36、总召类型 100；支持 SQ=0/1。保留传送原因的 test/negative 标志、源发地址及原始 ASDU。时标原样保留，不声明已经验证日历合法性。
- 收发错误、EOF、非法序号、非法帧及确认超时必须关闭会话并报告中文错误。TCP 分包、粘包不能误报有效帧。发送原始记录不能当作对端确认。

## 验收标准与测试顺序

先编写固定字节报文及边界用例，再实现相应逻辑。编译、类型检查和自动化测试统一由 GitHub Actions 执行。

1. 固定手写字节验证 U/S/I 帧、总召编码；分包、粘包、无效头、错误长度与控制域均有用例。
2. 遥信、双点、三种遥测及带时标格式验证地址、值、品质、时标、COT 与 SQ；截断、未知类型和信息地址溢出明确失败。
3. TCP 回环集成测试使用系统分配端口，验证 STARTDT → 总召 → 接收点值 → S 确认，以及 STOPDT/TESTFR 与断开处理。回环服务只模拟协议对端，不调用 DSP 内部接口。
4. 状态边界覆盖传输未启用、非法收发序号、15 位回绕、发送窗口、U/I 确认超时与延迟确认；定时逻辑尽可能用内部可控时刻验证，避免长时间睡眠。
5. 本提交完整 CI 通过格式、Clippy、核心与 workspace 测试和 Windows 打包。CI 成功不等于真机互操作验收；未执行的协议分支与真实设备验证如实记录。

## 桌面状态

本轮保持 `protocol_ready=false`，桌面建立连接、总召和命令按钮仍禁用。内核具备能力后须另行接入命令桥与事件订阅，才能通过安装版进行人工操作。

## 调用接口

`Session::connect(ConnectionConfig, SessionOptions)` 仅建立 TCP，初始传输状态为 `Stopped`。调用 `start()` 后持续 `poll()`，直到 `transfer_state()` 为 `Started` 才能调用 `interrogate()`。`interrogate()` 只发送总召激活，调用者须根据 ASDU 类型100、CA、COT7/10、negative 标志自行关联确认与终止；首版没有“总召完成”状态或自动成功判定。

`poll()` 返回 `Vec<Event>`，其中 `Frame` 记录收发原始字节，`Asdu` 提供解析对象，`ParseError` 保留不支持或无效 ASDU 的错误。解析错误与链路错误分开：未知 ASDU 不导致链路断开。`poll()` 失败后必须调用 `drain_events()` 取得仍在队列中的报文及故障证据。定时器只有调用会话方法时才推进，调用者不得长期停顿后继续假设连接健康。

单次读取最多等待 `read_timeout`，并按最近定时器期限缩短；自动协议回复仍是同步写入，可能等待写超时 t1。因此会话应由专用工作线程驱动，不在界面线程直接调用。`SendFailure` 记录失败发送尝试的完整目标字节和错误；这些字节可能已部分发送，不能视为对端完整接收或确认。

`stop()` 发起 STOPDT，收到确认后成为 `Stopped`；`disconnect()` 立即关闭 TCP，不自动发送 STOPDT。丢弃会话对象也会关闭套接字。首版只提供协议事件，不维护点表缓存；调用者可依据事件 CA/IOA 建立缓存，但不能把缓存值认定为本轮接收。
