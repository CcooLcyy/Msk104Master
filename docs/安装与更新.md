# 安装与 R2 更新

## 范围与验收

- Windows x64 交付 NSIS 安装包，按当前用户安装；WebView2 缺失时由安装程序联网下载引导安装。
- 程序打开后自动检查一次更新，之后每 60 秒检查一次，也可手动检查；自动或手动检查发现新版本后立即下载并验证 Tauri 签名，再运行安装程序并退出旧进程，无需用户点击确认，不因现有连接或测试而延迟更新。
- 安装失败显示中文错误并保留手动重试入口，下一分钟重新检查并自动尝试更新；无新版本不触发安装。窗口关闭后，未完成的检查不得再触发安装。
- 自动检查、手动检查与安装共用操作锁；检查或安装尚未结束时跳过本轮自动检查，不排队补发。网络失败后下一分钟继续尝试，窗口关闭时清理定时器。
- R2 与 slaveSim 共用存储桶 `mskdsp-update`，独立前缀 `msk104master/ci`；不改动或清理其他项目对象。
- 仅 GitHub 本仓库 `main` 的 push/手动运行且开启发布变量时发布；其他分支及 PR 归档未签名安装包。
- CI 版本为基础版本加 `-ci.<CI_VERSION_BASE + github.run_number>`；每次发布可比较升级。当前未定义 Stable/Beta 通道。
- CI 校验源码、依赖和发布输入；实际安装、卸载与从旧版本升级需 Windows 桌面实测，不能以 CI 编译成功替代。

## CI 与密钥

Windows 与 Linux 作业使用 GitHub 托管 Runner。更新签名密钥存放于 `ci` 环境，R2 凭据可配置在该环境或仓库 Secrets 中。环境分支限制、密钥、版本基数与发布开关见 [GitHub Actions](GitHub-Actions.md)。未配置密钥时先运行未签名检查构建，不能将其当作自动更新发布成功。

更新地址：`https://pub-19f3d71852b04011b120b1b814141c12.r2.dev/msk104master/ci/latest.json`。

发布前校验本次流水线与构建记录、安装包及签名的 SHA256；安装包及签名放入版本与内容指纹目录，上传并验证后最后切换 `latest.json`。旧流水线与过期分支提交不能覆盖新清单。客户端以签名保证更新包真实性。

从 Actions 运行页下载 Windows 产物，归档内包含 `installer/`、`msk104master.exe`、`SHA256SUMS.txt` 和 `build-info.json`。首次安装请运行 `installer/` 内的 NSIS 安装包。已安装版本通过界面检查更新。

依赖变更时更新并提交相应的 `Cargo.lock` 或 `package-lock.json`。流水线用 Cargo `--locked` 和 `npm ci` 安装锁定版本。
