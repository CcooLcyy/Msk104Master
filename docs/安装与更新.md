# 安装与 R2 更新

## 范围与验收

- Windows x64 交付 NSIS 安装包，按当前用户安装；WebView2 缺失时由安装程序联网下载引导安装。
- 程序打开后自动检查一次更新，之后每 60 秒检查一次，也可手动检查；自动或手动检查发现新版本后立即下载并验证 Tauri 签名，再运行安装程序并退出旧进程，无需用户点击确认，不因现有连接或测试而延迟更新。
- 安装失败显示中文错误并保留手动重试入口，下一分钟重新检查并自动尝试更新；无新版本不触发安装。窗口关闭后，未完成的检查不得再触发安装。
- 自动检查、手动检查与安装共用操作锁；检查或安装尚未结束时跳过本轮自动检查，不排队补发。网络失败后下一分钟继续尝试，窗口关闭时清理定时器。
- R2 与 slaveSim 共用存储桶 `mskdsp-update`，独立前缀 `msk104master/ci`；不改动或清理其他项目对象。
- 仅受保护 `main` 的 push/web 流水线发布。其他分支/MR 只归档未签名安装包，不发布。
- CI 版本为基础版本加 `-ci.<CI_PIPELINE_IID>`；每次发布可比较升级。当前未定义 Stable/Beta 通道。
- CI 校验源码、依赖和发布输入；实际安装、卸载与从旧版本升级需 Windows 桌面实测，不能以 CI 编译成功替代。

## CI 与密钥

Windows 作业使用 `ci` 环境，继承现有 Runner。签名需要受保护 CI 变量 `TAURI_SIGNING_PRIVATE_KEY` 及可选 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`，公钥与上位机现有签名公钥保持一致。Linux 发布作业复用 slaveSim 的发布镜像，需要受保护变量 `R2_ACCOUNT_ID`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`。密钥只保存在 GitLab 变量中，不回显或归档。

更新地址：`https://pub-19f3d71852b04011b120b1b814141c12.r2.dev/msk104master/ci/latest.json`。

发布前校验本次流水线与构建记录、安装包及签名的 SHA256；安装包放入版本独立目录，上传并验证后最后切换 `latest.json`。旧流水线与过期分支提交不能覆盖新清单。客户端以签名保证更新包真实性。

CI 归档 `package/installer/`、`package/SHA256SUMS.txt` 和 `package/build-info.json`，可从流水线下载 NSIS 安装包首次安装。已安装版本通过界面检查更新。

新增 Rust 依赖时，如锁文件需引导刷新，使用显式流水线变量 `ALLOW_LOCKFILE_BOOTSTRAP=1`，从同次 CI 回收 `Cargo.lock` 并提交；日常流水线保持 `--locked`。
