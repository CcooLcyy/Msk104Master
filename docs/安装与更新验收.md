# 安装与更新验收

## 范围

交付 Windows x64 NSIS 安装包，支持首次安装、卸载和覆盖升级。更新资产沿用 slaveSim 的 R2 存储桶，使用独立 `msk104master/ci` 前缀和 Tauri 签名清单。主站协议功能不在本次范围内。

## 行为与异常

- 打开程序自动检查一次，此后每 60 秒检查一次；保留手动检查入口。自动或手动检查发现新版本即自动下载、校验并安装，无需确认，也不等待现有连接或测试结束；无新版本不安装。
- Rust 保存已检查的更新对象；安装使用该对象，不能由界面传入任意下载地址。
- 检查与安装串行执行；网络错误、无候选版本和签名错误均显示中文信息并可重试。
- 检查或安装未结束时跳过定时触发，不积压请求；检查或安装失败后下个周期重新检查并自动更新，安装失败也可手动重试。组件卸载清理首次检查和周期计时器，进行中检查结束后不再触发安装或更新已卸载界面。
- 检查失败清空旧候选，不能将失败展示为已是最新版本；下载与签名校验失败不得安装。
- Windows 安装会退出当前程序，由安装器升级并重新打开；界面提前告知。
- CI 校验版本、安装器与签名后先上传资产，最后更新 latest.json，公共下载核验成功才算发布成功。

## 验收标准

1. 对应提交的 GitHub Actions 通过格式检查、Clippy、单元测试、更新调度行为测试、前端构建和 NSIS 打包，归档安装器与签名。
2. CI 发布独立 R2 清单，清单中的 Windows 资产可下载且摘要与归档一致。
3. 人工安装后可打开中文工作台，应用信息显示当前构建版本；可卸载。
4. 旧安装版本检查到新版本后无需点击即可下载安装升级，包括有连接或测试进行中的情况；断网、无更新和无候选安装有明确提示。首次获得本能力仍需通过旧版本原有安装入口完成升级。
5. 签名不合法的更新被拒绝；安装和跨版本升级属于人工验收，不能仅凭构建通过宣称完成。
6. 更新调度使用模拟时钟和更新命令验证：启动检查、60 秒间隔、手动与自动检查发现新版本即安装、无更新不安装、操作互斥、安装期间暂停、失败后重试和卸载后不安装；由 CI 的前端构建入口执行，不请求真实更新服务。
